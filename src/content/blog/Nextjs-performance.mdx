Core Web Vitals scores don't move because you read an article about them —
they move because a handful of specific bottlenecks get fixed one at a time.
Here's what actually mattered, in the order I found the issues.

## LCP: the image was never the bottleneck I expected

Everyone blames the hero image for a slow Largest Contentful Paint. In my
case, the image was already optimized — the real problem was a client-side
data fetch blocking the entire render.

```tsx
// Before: LCP waited on a client fetch
"use client"
function Hero() {
  const { data } = useSWR("/api/hero", fetcher)
  if (!data) return <Skeleton />
  return <HeroContent data={data} />
}

// After: data fetched on the server, streamed in immediately
async function Hero() {
  const data = await getHeroData()
  return <HeroContent data={data} />
}
```

Moving data fetching into a server component cut LCP by roughly 900ms on the
homepage, without touching the image at all.

## Code splitting where it actually pays off

Not every dynamic import is worth it — splitting a 4kb component adds a
network waterfall for no real gain. The wins came from isolating genuinely
heavy, below-the-fold dependencies:

- Charting libraries loaded only when a dashboard tab is opened
- A rich text editor loaded only behind an "Edit" action
- Map components loaded with `next/dynamic` and `ssr: false`

```tsx
const Chart = dynamic(() => import("./chart"), {
  loading: () => <ChartSkeleton />,
  ssr: false,
})
```

## Fonts were quietly causing layout shift

`next/font` solved most of this automatically, but the remaining Cumulative
Layout Shift came from a font-weight swap that wasn't declared in the
`@font-face` fallback metrics. Setting explicit `size-adjust` values on the
fallback font brought CLS from 0.18 down to 0.02.

> If your Lighthouse score looks fine locally but real-user CLS is still bad,
> check for font swaps and any content that loads after an ad or embed slot
> reserves zero height.

## The results

| Metric | Before | After |
| --- | --- | --- |
| LCP | 3.4s | 1.6s |
| CLS | 0.18 | 0.02 |
| TBT | 410ms | 90ms |

None of these fixes were exotic. They were the result of profiling first and
guessing second — which, in hindsight, should have been the plan from the
start.
